# 星桥文档服务：索引管理

本文件为自编的星桥 v1.0 技术演示资料。

## 持久化格式

每个模式的索引包含 vectors.npz、chunks.json 和 manifest.json。向量采用 float32 和 L2 归一化，矩阵每一行严格对应同一位置的文档片段，加载 npz 时禁用 pickle。

manifest 记录文档 SHA-256、语料指纹、嵌入身份、向量维度、切分配置和产物哈希。这里只做小规模精确检索，不是 ANN，也不是分布式向量数据库。

## 重建条件

文档新增、删除或修改，嵌入适配器、服务地址、嵌入模型或切分参数改变，都必须重新构建索引。索引文件损坏同样要求重建。

只修改聊天模型不需要重嵌入，因为聊天模型不决定文档向量空间。同名远端嵌入模型悄悄更新时，本地身份检查未必能够检测到变化。

## 发布与恢复

新构建先写入独立目录并完成自检，之后原子替换 current.json 指针。构建或指针替换失败时，旧指针和旧构建继续保留，不发布半成品。

启动与每次查询都会检查索引兼容性，发现不兼容返回 503 INDEX_REBUILD_REQUIRED；索引从未构建时返回 503 INDEX_NOT_READY。API 不会偷偷后台重建索引。v1.0 只支持单个构建进程。
