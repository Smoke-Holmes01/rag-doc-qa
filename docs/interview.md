# 理解与面试复述材料

本文件是 AI 辅助整理的学习材料，不代表项目所有者已经掌握全部实现或亲自完成验证。应先运行命令、读代码并自己复述，再用于面试。

## 为什么不使用向量数据库？

这是固定本地六份文档的小规模演示，目前切成 22 个片段。把向量存成 NumPy 矩阵，对全部片段精确打分已经足够，也便于解释来源与兼容性。它不是 ANN，不具有分布式数据库能力；数据量变大后才有必要评估索引结构、延迟、更新和权限等问题。

余弦相似度等于两个向量的点积除以范数乘积。先各自除以 L2 范数变成单位向量，之后矩阵点积就是余弦。零向量没有可用方向，NaN/Inf 也不能参与有效排序，所以必须明确拒绝。

## 为什么标题、段落和重叠影响检索？

一段“默认 30 秒”的正文如果缺少标题，模型可能不知道它说的是超时。章节路径提供语境；按段落切分能尽量把条件和例外保留在一起。太长会引入无关主题，太短会割裂事实。重叠帮助长段跨边界保留联系，但也会重复召回、浪费上下文预算，因此这里只对超长段使用。

## 为什么查询只嵌入问题？换嵌入模型为什么要重建？

文档向量已经在离线构建时算好，查询只需把当前问题放进同一个向量空间。每次重算整库会浪费调用和延迟，也让索引边界难以追踪。不同嵌入模型即使输出维度相同，坐标含义也不一致，不能直接比较。聊天模型只阅读检索文本，不决定向量空间，单独更换它一般无需重建。

## 来源 ID 合法与结论受到支持有什么区别？

程序可以确认这个 ID 是本次发送的片段，并从本地回填原文。它不能仅凭 ID 判断模型是否曲解、遗漏例外或引用无关文字。F06 的 mock 摘录包含合法错误码来源，却没有回答超时数值，正好展示这个边界。

## 有检索内容为什么仍会错？怎样判断资料不足？

可能检索到相近但不回答问题的内容，组合问题缺少一条依据，或者生成时误读数字和否定条件。资料不足需要核对问题的每个必要事实是否都能在提供片段中找到；仅出现关键词或一条引用不足以判断。评测把上下文依据覆盖与回答逐条语义核验分开，尚未核验时保留 pending_review。

## 怎样隔离 mock 和定位失败？

mock/live 配置、索引目录、响应 mode 和报告分开；live 缺配置或调用失败不会 fallback。mock 只证明工程路径能跑，其哈希向量不是 BGE-M3，摘录器不是 LLM。

先看错误码：超时、认证、限流是接口层；运行成功但预期原文没进入实际上下文是检索/预算层；上下文有完整依据但答案不符合原文则要检查生成和语义支持。request_id、来源 ID、分数、字符数和耗时能帮助定位，完整用户问题与供应商原始响应默认不写日志。
